SolidJS consumes the <u-*> elements natively — it scores a perfect 16/16 on Custom Elements Everywhere. There is no runtime wrapper (solid-element is for authoring web components, not consuming them). Two gotchas matter: camelCase prop keys get lowercased, and genuine custom events need on:exact-name. The bare side-effecting import runs every customElements.define. It has side effects, so it won't be tree-shaken away. On a custom element, foo={{ '{' }}x{{ '}' }} sets a JS property by default — exactly right for Lit. But Solid lowercases the bare prop key, so use prop:camelCaseName for any camelCase or non-string property; bare kebab-case is fine for plain string attributes.
Directive Effect Use for
prop:foo or .foo force a JS property camelCase props, complex values
attr:foo force an HTML attribute (null/undefined removes it) reflected string attrs, SSR-visible attrs
bool:foo or ?foo boolean attribute (present when truthy) presence-style boolean attrs
Native input/change are in Solid's delegated set, so onInput/onChange work (value on e.currentTarget.value). Genuine CustomEvents are NOT delegated and the delegated handlers lowercase names — so use on: with the exact, case-sensitive event name. Shadow-DOM events must be composed: true to escape (ours are). Solid has no v-model sugar — binding is explicit. Mental model: two-way value ≡ prop:value={{ '{' }}x(){{ '}' }} in + on:input/on:change reading e.currentTarget.value out.
Component(s) Write in (with prop:) Read value out from
u-text-field, u-text-area, u-search value: string input → e.target.value
u-datepicker, u-range-datepicker value: string input + change → e.target.value
u-select value: string (+ selectedIndex) change (not composed) → e.target.value
u-checkbox, u-switch, u-radio checked: boolean input + change → e.target.checked
u-slider value: number (or valueStart/valueEnd) input + change → e.target.value
u-chip-field value: any[] change → e.target.value; remove is a CustomEvent
u-typeahead value: any input/change → e.target.value; selected is a CustomEvent
u-button-field value: string (display-only) none — set programmatically
Augment solid-js' JSX.IntrinsicElements with one entry per u-* element. The augmentation can be hand-written or code-generated from dist/custom-elements.json. Type the genuine CustomEvent handlers (on:selected on typeahead, on:remove on chip field). customElements is undefined on the server, so register client-side only — import in a client-only entry or guard the registration import behind an isServer check in Solid Start.
