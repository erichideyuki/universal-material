Svelte 4 and Svelte 5 consume the <u-*> elements natively — it has the best out-of-the-box custom-element support of any target framework. There is no runtime wrapper, no Vite plugin and no build config to add. (The customElement: true compiler option is for authoring custom elements and must not be enabled.) Register the library eagerly so the elements are defined before first render — Svelte's prop in node heuristic reads the live instance, so an unupgraded element falls back to attribute-setting. In SvelteKit, guard the import to the client (browser / onMount); a plain Vite SPA can import at the top level. Write the value in as a normal prop and read changes back with on:input / on:change. Read e.target.value / e.target.checked, NOT e.detail — e.detail is reserved for genuine CustomEvents like u-typeahead's selected and u-chip's remove.
Component(s) Two-way prop Live event Read-back
u-text-field, u-text-area, u-search value: string input (+ change) on:input → e.target.value
u-datepicker, u-range-datepicker value: string input + change on:change → e.target.value
u-select value: string input + change (not composed) on:input → e.target.value
u-checkbox, u-switch, u-radio checked: boolean change on:change → e.target.checked
u-slider value: number input + change on:input → e.target.value
u-chip-field value: any[] change on:change → e.target.value
u-typeahead value: any input/change + selected (CustomEvent) value via e.target.value; pick via on:selected → e.detail
bind:value does NOT work on third-party custom elements — it is reserved for native form elements and Svelte components. Use prop-in + on:input/on:change, or wrap the element once in a thin .svelte component to recover a real bind:value (bind: works on Svelte components). Svelte's prop in node heuristic sets a property when one exists on the live instance, else an attribute. If the element isn't upgraded yet, an object becomes [object Object]. Register the library eagerly, or assign properties imperatively with a use:setProperties action / bind:this + $effect. Augment svelte/elements' SvelteHTMLElements interface with one entry per u-* tag for attribute/event autocompletion. This is DX sugar — the tags render and work without it. customElements / HTMLElement are browser-only — a top-level server import throws HTMLElement is not defined. Import client-side only (inside onMount, behind the browser flag, or export const ssr = false as a last resort).
