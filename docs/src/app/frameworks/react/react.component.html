@universal-material/react ships one typed wrapper per <u-*> element (UButton, USelect, UTextField, UCheckbox, …), generated with @lit/react's createComponent. The wrappers set known props as DOM properties (so the IDL setters and form participation work), wire the elements' events as typed on* handlers, and work on React 17, 18 and 19. @universal-material/web and react/react-dom are peer dependencies — install them alongside the wrapper package. Importing anything from @universal-material/react also imports @universal-material/web once for its side effect, which registers every <u-*> custom element — so you do not need a separate registration import. The value goes in as a DOM property (value / checked) and comes out by listening to input (live) / change (committed) and reading e.target.value (or e.target.checked). The per-element contract:
Component(s) Two-way prop Events to map Read value from
UTextField, UTextArea, USearch value: string onInput + onChange e.target.value
UDatepicker, URangeDatepicker value: string onInput + onChange e.target.value
USelect value: string (+ selectedIndex) onInput + onChange e.target.value (IDL prop only — no value attribute)
UCheckbox, URadio, USwitch (+ *ListItem) checked: boolean onChange e.target.checked
USlider value: number or valueStart/valueEnd onInput + onChange e.target.value
UChipField value: any[] onChange + onRemove (CustomEvent) e.target.value
UTypeahead value: any onInput + onChange + onSelected (CustomEvent) e.target.value
Selection controls are not text inputs: bind checked, listen on onChange, and read e.target.checked. Because every input is a Form-Associated Custom Element, native <form> / FormData submission and constraint validation are free. Give each element a name, read it on submit, and keep zero React state — the simplest path. Prefer register (uncontrolled) — the FACE value is already on the form. Use Controller when RHF must own the value, bridging field.value → value and onChange/onInput → field.onChange(e.target.value). UTypeahead's onSelected and UChipField's onRemove are CustomEvents — read the payload from e.detail (the value itself still comes from e.target.value). Custom elements are client-only — they call attachInternals() in their constructor, which throws during server rendering. Render the wrappers from a 'use client' component, and fall back to next/dynamic with {{ '{' }} ssr: false {{ '}' }} if the constructor is evaluated eagerly.
