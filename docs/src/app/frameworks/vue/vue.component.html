Vue 3 consumes the <u-*> elements natively — there is no runtime wrapper to install. The one mandatory step is telling the template compiler that u-* tags are custom elements via isCustomElement; prop binding, event listening and v-model then work out of the box. Without this, Vue logs Failed to resolve component: u-button. isCustomElement is a compile-time option, so it must go in the build config (Vite / Vue CLI), not app.config.compilerOptions. Prefer the precise tag.startsWith('u-') predicate over the broad tag.includes('-'). Import @universal-material/web once for its side effect — that runs every @customElement('u-…') registration. Vue checks whether a binding key exists as a DOM property on the element (an in check) and sets it as a property when it does, else an attribute. Use .prop to force a property and .attr to force an attribute when the heuristic guesses wrong. Listen with @event and read the payload off the native event. Because a tag matched by isCustomElement is a plain element, Vue uses the native v-model expansion (:value + @input), not the component modelValue/update:modelValue expansion.

Mental model: on a u-* element, v-model="x" ≡ :value="x" @input="x = $event.target.value". When the component doesn't expose value + input, bind :prop and @event explicitly.

Component(s) Two-way prop Live event (where value lives) Recommended binding
u-text-field, u-text-area, u-search value: string input; value on $event.target.value v-model="text"
u-datepicker, u-range-datepicker value: string input + change; $event.target.value v-model="date"
u-select value: string input + change (not composed); $event.target.value v-model="choice" or :value + @change
u-checkbox, u-switch, u-radio checked: boolean change; value on $event.target.checked :checked + @change="x = $event.target.checked"
u-slider value: number (or valueStart/valueEnd) input + change; $event.target.value v-model.number="n" (single)
u-chip-field value: any[] change (array, not at target.value… read $event.target.value) :value + @change="rows = $event.target.value"
u-typeahead value: any input + change + selected (CustomEvent) :value + @input; @selected reads $event.detail
u-button-field value: string (display-only) none one-way :value only
Augment Vue's GlobalComponents with the DefineCustomElement<> helper so <u-*> tags get autocomplete and type-checking in templates. Pass the element class (the Lit Button, Select, …) so its @property fields become typed template props. Without it the tags still render — you just lose IntelliSense. Custom elements aren't defined on the server (customElements is undefined in Node). Import the library and render u-* tags client-side only — a Nuxt .client.ts plugin with <ClientOnly> or an import.meta.client guard — or you'll hit customElements is not defined / hydration mismatches.
